# v2.16.2 — 혼합 입력의 단타 LN 오인식 수정

2026-10-28 Windows x64 핫픽스. 상단 단수와 4K LN 등급에 적용한다.

## 원인과 수정

보조지표는 v2.16에서 170ms 홀드 추정으로 바뀌었지만, 주 난이도에는 90ms 기준이 남아 있었다. 이 때문에 롱노트를 유지하며 단타를 조금 길게 누르면 단타까지 LN으로 처리되고 홀드·릴리즈 간섭 부담이 추가됐다. 상단 Reform과 4K LN 등급은 같은 주 난이도 부담을 서로 다른 기준표에 비교하므로 둘 다 올라갈 수 있었다.

실타건 주 난이도도 **170ms 미만은 단타, 170ms 이상은 LN 추정**으로 통일한다. 보조지표와 같은 상수를 공유해 두 경로가 다시 어긋나지 않도록 했다. 누르고 있는 키도 현재까지 관측한 시간으로 구분한다. LN 부담 2/3 수식·단위 기준표·기본 노트 밀도는 변경하지 않는다. v2.16.1의 최소 650×300px와 완료값 보존, 보조지표의 8초/0.5초 갱신은 유지한다.

파일은 실제 노트 끝점을 알고 있으므로, 선택 채보·파일 분석·기준표 추출은 명시적으로 기존 90ms 재생 기준을 사용한다. 기존 파일 계산과 기준표의 재현성을 보존하려는 구분이다. 물리 타건과 파일 재생은 시작 시각이 같아도 관측된 해제 시각·판정 정책이 달라 결과가 같을 필요가 없다.

## 재현 결과

모든 노트 머리와 실제 LN 길이를 고정하고 단타 유지 시간만 바꾼 합성 4K 입력이다. 수치는 현재 코드의 내부 부담값이며 실제 곡 정확도를 뜻하지 않는다.

| 조건 | 수정 전 | 수정 후 |
|---|---:|---:|
| 단타만, 10ms 해제 | 2.304509 | 2.304509 |
| 같은 단타, 120ms 해제 | 3.406051 | 2.304509 |
| LN 유지 + 단타, 10ms 해제 | 2.869268 | 2.869268 |
| 같은 LN 유지 + 단타, 120ms 해제 | 4.246196 | 2.869268 |
| 250ms LN만 | 3.406048 | 3.406048 |

혼합 사례의 잘못된 추가 상승은 약 48.0%였다. 수정 후 단타를 90·120·150·169.999ms 눌러도 10ms 단타와 동일한 주 난이도·완료 단수·4K LN 단수가 나온다. 170ms부터는 LN 추정 부담을 유지한다. 진짜 LN도 인식 시점이 늦어지므로 일부 패턴의 과거 최고값은 달라질 수 있으며, 이미 LN으로 확정된 동일 구간의 strain 수식은 그대로다.

## 검증과 한계

4~10K의 단타·지속 LN+단타·엇갈린 혼합 패턴을 현재값과 완료 최고값 양쪽에서 검사한다. 네이티브 UI 입력 수집 경로도 10ms/120ms 혼합 입력의 상단 단수와 4K LN 결과가 같은지 검사한다. 원본 v2.16.1과 수정본의 파일 재생은 5개 키 모드·6개 길이·2개 가중치, 60개 합성 경우에서 모든 시간 표본과 요약값이 동일했다.

일반판·NoOsuMemory 각각 CTest **11/11**, 파일 분석기 **3/3** 통과. 주 난이도 **465개**, 실시간 보조 계산 **262개**, 네이티브 UI 일반판 **304개**·NoOsuMemory **288개** 검사를 통과했다. 파일 재생의 120ms LN 기준값을 영구 회귀검사에도 추가했다.

실제 사용자 채보·게임 입력·OBS·다른 PC/DPI·장시간 사용은 미검증이다. 170ms 이상 누른 단타는 여전히 LN으로 오인할 수 있고 170ms 미만의 실제 짧은 LN은 실타건에서 단타로 추정될 수 있다. 이번 수정은 재현된 단타 오인식 경로를 해결하며, 모든 혼합 채보의 체감 난이도가 정확해졌다는 의미는 아니다.

일반판과 NoOsuMemory ZIP을 새 폴더에 풀어 사용한다. 이전 릴리즈와 개인 설정은 보존한다. 패키지의 `VERIFICATION.md`에 검증 결과와 소스 커밋을 기록한다.
