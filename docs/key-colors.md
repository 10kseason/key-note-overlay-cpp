# 키별 색상·불투명도 v2.9

설정의 **키 색상** 탭에서 현재 배치의 키를 고른다. 색상 선택 창 또는 `#RRGGBB` / `RRGGBB` 입력을 사용할 수 있다. 빈칸은 기존 순서별 팔레트, 불투명도는 0~100 정수다. 체크무늬 미리보기는 편집 값이며 실제 오버레이는 **적용**, 다음 실행까지 보관하려면 **적용 + 저장**을 누른다.

- 0%: 노트·롱노트·그림자·글자·잔상 모두 숨김. 입력과 NPS·난이도는 계속 계산한다.
- 50%: 노트 전체를 뒤쪽 화면 또는 오버레이 배경과 반투명 합성.
- 100%: 기존 불투명 노트 모양.
- 전체 불투명도도 50%이고 키 불투명도도 50%이면 노트 기여도는 약 25%다. 겹친 노트는 각각 합성된다.
- 위치 확인용 배경·레인 배경·난이도 HUD는 키별 설정의 영향을 받지 않는다. 뒤쪽 게임이 보이게 하려면 필요에 따라 배경을 끈다.

색과 불투명도는 레인 번호가 아닌 실제 키에 저장한다. D키를 이동하거나 4K/10K 프리셋을 전환해도 D키 값이 유지된다. 숫자패드와 좌우 Shift/Ctrl/Alt는 각각 설정할 수 있다. 배치에서 잠시 뺀 키의 설정도 보관한다. 다른 키로 교체하면 새 키의 설정을 사용한다. 테마는 키별 지정을 덮어쓰지 않는다.

**선택 키 기본값**은 선택한 키의 지정만 해제한다. **저장 상태로 되돌리기**는 다른 설정과 함께 마지막 저장 상태로 복원한다. 미완성 HEX·범위 밖 불투명도는 다른 키로 이동해도 편집 상태에 남으며 적용·저장 시 해당 키를 안내한다.

## 저장 호환

기존 JSON에 선택 항목 `key_styles`를 추가한다. 항목이 없으면 기존 팔레트·100%를 사용한다. 기본값인 키는 저장 시 생략한다. 예:

```json
"key_styles": {
  "key_color_D": "#FF4664",
  "key_opacity_D": 50,
  "key_opacity_SPACE": 0
}
```

호환 INI는 `[key_styles]`에 `color_D=#FF4664`, `opacity_D=50`, `opacity_SPACE=0`을 사용한다. 이전 버전은 새 항목을 사용하지 않으므로 이전 EXE로 다시 저장하면 지정이 사라질 수 있다. 배포본에는 개인 설정이 아닌 기본 설정만 들어 있다.

## 구현과 검증

기존 색상 키 방식은 창 전체의 불투명도만 지원하므로, 자체 GDI 렌더 결과를 BGRA로 합성해 [UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow)로 표시한다. [GDI가 그린 픽셀의 상위 바이트를 0으로 쓰는 동작](https://devblogs.microsoft.com/oldnewthing/20210915-00/?p=105687)을 사용해 빈 픽셀과 그려진 픽셀을 구분한다. 검정과 이전 투명색 `#010203`도 일반 색으로 지정할 수 있다. 키별 불투명도는 노트를 합성할 때, 전체 불투명도는 창을 표시할 때 적용한다. 새 외부 라이브러리는 필요하지 않다.

숨겨진 네이티브 UI 검사에서 키별 편집·순서/프리셋/테마 변경·JSON/INI 재로딩·잘못된 값·기본값/되돌리기를 확인한다. 같은 렌더러의 실제 픽셀로 0/50/100%, 검정, 이전 투명색, 원형·롱노트·겹침, HUD 분리를 검사하고 숨겨진 실제 layered 창에 전송한다. 공개 배포 전 자동 검사는 실제 OBS 캡처·게임 플레이·다중 DPI 화면 검증을 대신하지 않는다.
