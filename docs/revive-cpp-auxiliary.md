# Revive CPP 6개 스킬 · 선택 채보와 실시간 입력 — 2026-10-28

osu! 연동을 사용자가 켠 동안, 선택한 **원본 1~18K 채보**에 필요한 스킬을 보조 정보로 표시한다. 설정의 **osu! 연동** 탭에는 `Revive CPP · 요구 스킬: 홀드 / 연타`처럼 상위 두 항목과 여섯 항목의 특징 강도가 나온다. HUD에는 **스트림·속도·연타·동시치기·테크닉·홀드 6개 모두** 이름·정수 수치·막대로 표시한다. 확인된 0도 생략하지 않고, 미지원·대기 중에는 여섯 칸을 `—`로 표시한다. 실시간 입력의 홀드는 타건만으로 판별할 수 없어 항상 `—`(미확인)이며 막대도 표시하지 않는다. 선택 채보는 실제 LN이 없을 때 홀드 0, 있을 때 원본 수식으로 계산한 값을 표시한다. 실시간 제목은 `보조지표`, 선택 파일은 `채보 보조지표`다. 이름은 22px, 수치는 26px(가로 칸) 또는 32px(세로 칸) 굵은 글씨다. 폭 900px 이상은 6열, 456~899px은 3열, 240~455px은 2열이다. 칸 폭이 148px 미만이면 이름과 값을 두 줄로 나눈다. `4K LN` 이름은 22px, 결과는 최대 32px이며 긴 결과는 실제 폭에 맞춰 줄인다. Revive LV는 화면에 표시하지 않는다.

| 표시 | 원본 축 | 해석 |
|---|---|---|
| 스트림 | STREAM | 지속적인 노트 흐름 처리 |
| 속도 | SPEED | 높은 순간 밀도와 빠른 입력 |
| 연타 | JACK | 같은 레인의 반복 입력 |
| 동시치기 | CHORD | 여러 키 동시 입력과 동시치기 반복 |
| 테크닉 | TECH | 레인 이동·손배치 변화 대응 |
| 홀드 | HOLD | 롱노트 유지·해제와 다른 입력의 간섭 |

여섯 값은 원본 리바이브 스킬 레이더의 정규화된 **0~100 특징 강도**다. 순위는 반올림 전 값으로 정하고 화면 숫자는 정수로 표시한다. 동점은 표의 순서를 유지하며 모두 0이면 `특징 부족`으로 표시한다. 플레이어의 실력 등급이나 합격에 필요한 최소 능력 수치를 뜻하지 않는다. 선택 채보 보조값은 연동 OFF, 새 채보 분석, 파일 오류, 게임 종료 시 지워진다. 실시간 보조지표는 연동 OFF에서도 계속 계산한다. 1~18K 범위 밖의 키 수는 `1~18K 지원`으로 표시하고 보조값을 보류한다.

## 계산 의미

- 보존된 C++ 이식본의 **1~18K·스크래치 없음·고정 배치·auto 목표·qwilight_bms_ez** 설정을 사용한다. osu! OD 또는 현재 게임 판정에 맞춘 값이 아니다.
- 원본 1.00배의 **전체 파일**을 계산한다. LN은 머리/꼬리를 각각 전달하며 단타에는 가상의 꼬리를 추가하지 않는다. 첫 노트부터 마지막 노트/꼬리까지를 연주 길이로 사용한다.
- 기존 주 난이도는 실시간과 같은 최고 구간 추정치다. Revive CPP의 전체 파일 스킬 레이더는 별도 수식이므로 기존 단위값에 더하거나 섞지 않는다. 주 난이도 수식과 5K/10K 기준표는 유지한다. 별도의 실시간 CPP 지표는 아래 관측 창을 사용한다.
- DT/HT, 키 변경, Co-op, 변환 채보, 랜덤 배치, FC/Perfect 목표, osu! OD 보간은 지원하지 않는다. 공식 난이도나 정확도 개선을 입증한 지표가 아니다.

## 실행 경계

게임 메모리에서 읽는 항목은 기존 폴더명·파일명·MD5 그대로다. 추가 메모리 탐색 없이 이미 확인한 `.osu` 파일의 노트를 계산한다. 계산 후에도 선택 정보와 MD5를 재확인하며, 바뀐 곡의 결과를 게시하지 않는다. 같은 파일/선택/수정 시각에서는 기존 캐시를 재사용한다.

계산은 기존 파일 분석 작업 스레드에서 수행한다. 최대 40,000이벤트(LN 꼬리 포함), 2초 구간 최대 2,048이벤트, 네이티브 계산 1.5초 한도를 둔다. 시간 확인 사이의 연산·정렬 시간만큼 한도를 약간 넘을 수 있다. 연동을 끄면 취소 플래그를 확인한다. 한도 초과·지원하지 않는 입력은 보조지표만 보류하며 주 난이도 결과를 유지한다.

판정표와 계수는 `src/revive_config.h`, 키별 행렬은 `src/revive_key_matrices.h`에 고정되어 있어 별도 Python/YAML/설정 파일 설치가 필요 없다. 기본 OFF·매 실행 동의 정책은 그대로이며 NoOsuMemory 빌드도 **실시간 보조지표**는 포함한다. 게임 메모리 리더와 선택 채보 UI는 포함하지 않는다. 선택 채보나 보조 결과를 설정·연주 리포트에 새로 저장하지 않는다.

## 실시간 보조지표

- 난이도 분석을 켜고 **등록/분석 키 수 1~18K**에서 입력하면 최근 8초의 특징을 계산한다. 선택 채보를 읽지 않으므로 osu! 연동이 꺼져 있거나 NoOsuMemory 빌드여도 동작한다. 각 키 수의 원본 손배치·시각 거리 행렬을 사용하되 실시간 입력은 누름 시점만 단타 머리로 전달한다. 1~3K·11~18K는 직접 키를 등록한 뒤 `등록 키 수 (기존)`으로 사용한다. 자동/수동 선택 범위는 기존 4~10K다.
- 최소 8회 입력·1.5초 관측 후, 0.5초마다 별도 작업에서 갱신한다. 대기·자동 키 추정 중·키 수 충돌·입력 한도 초과·초기화 때는 이전 수치를 지운다. 새 세션의 입력에 이전 세션 작업 결과가 섞이지 않는다.
- 누름/해제 중복을 제외한 실제 분석 입력만 수집한다. 설정 입력·키 등록·애니메이션 미리보기는 제외한다. 키를 오래 눌러도 채보의 LN 꼬리를 만들지 않는다. 이전 90ms 임계값은 단타의 느린 해제를 롱노트로 오인해 제거했다. 열린 키도 누름 시점 한 번만 반영하며, 시작점이 최근 8초 창 밖이면 제외한다. 해제·포커스 해제는 키 상태와 세션 관리에만 사용한다.
- `보조지표`는 **관측한 입력의 특징**이다. 실제 채보에서 빗나간 입력이나 미래 노트를 알 수 없으므로 `채보 보조지표`의 전체 파일 분석과 값이 같을 필요가 없다. 두 결과를 합산하거나 LV로 표시하지 않는다.
- 동시 계산은 하나, 입력 버퍼는 4,096누름, 계산 한도는 100ms다. 한도 확인 사이 작업만큼 실제 종료가 늦어질 수 있다. 결과를 기다리는 동안 입력/렌더링 스레드는 대기하지 않는다. 정지·초기화는 취소와 세대 검증으로 늦은 결과를 버린다.
- 최근 입력이 사라지면 `입력 대기`로 돌아간다. CPP 결과는 기존 주 난이도의 최고값 유지/완료 결과와 별개이며 리포트에 새로운 필드로 저장하지 않는다.

모든 지표와 노트 영역을 함께 보존하려고 실제 창 높이는 `저장 높이`와 `HUD + 노트 높이 + 여백` 중 큰 값을 사용한다. 저장 크기·위치는 덮어쓰지 않는다. 분석/HUD/선곡 연동을 끄면 필요한 높이도 줄어든다.

`revive_live` 검사는 비동기 결과의 5개 누름 축 일치와 홀드 미확인 표시, 90~500ms 단타 해제의 불변성, 8초 창, 열린 키, 포커스 해제, 초기화/취소, 키 수 제한, 버퍼 상한, 0.5초 주기와 최소 폭 레이아웃을 다룬다. 네이티브 UI 검사는 실제 입력 수집 경로에서 CPP가 갱신되는 것과 6개 칸이 모두 그려지는 것을 확인한다.

## 키별 행렬과 배치 대응

원본 `config.yaml`의 `weighted_nps.weights_Nk`와 `distance_difficulty.visual_distance_matrices.weights_Nk`를 N=1~18에 대해 내장했다. 각 일반 배치의 순서는 등록 레인 순서에 대응한다. 4K는 왼손 중지·검지, 오른손 검지·중지다. 스크래치 전용 배치는 이번 범위에서 제외한다. 계수와 Qwilight EZ 판정 조건은 공통이며, 홀드 점유율 분모와 계산 중 레인 순회/검증에는 실제 키 수를 적용한다.

더 큰 배치를 등록한 상태에서 수동 또는 자동 **4~10K**를 쓰면, 세션에서 해당 수만큼 서로 다른 레인이 관측된 뒤 등록 순서대로 대응한다. 예를 들어 4K는 네 레인이 확인되기 전 `4키 배치 확인 중`, 다섯 번째 레인이 입력되면 `키 수 확인`으로 보류한다. 일부 레인이 최근 8초 창에서 빠져도 대응 순서는 바뀌지 않는다. 10초 무입력 뒤 새 입력 또는 초기화로 세션 대응을 다시 시작한다. CPP의 분석 키 수 전환 시 진행 중인 이전 모드 결과를 버린다.

`tools/generate_revive4_fixtures.py`는 원본 계산기를 읽기 전용으로 실행해 합성 4K 입력 18종을 생성한다. 실제 곡·입력 로그를 테스트에 포함하지 않는다. `tests/fixtures/revive4/provenance.json`에 원본 해시와 행렬을 기록했다. 스트림·연타·2/4동시치기·스파이더·변박·겹친/엇갈린 홀드·4레인 점유·난수 혼합·단일/빈 입력을 다룬다. 고정 C++ 테스트는 이 6축과 내부 계산값을 Python 결과와 비교하며, 등록 4키·희소한 레인의 수동/자동 4K 경로도 검증한다. 원본과의 수치 일치는 플레이어 실력이나 실제 채보 체감의 정확도 검증이 아니다.

`tools/generate_revive_key_support.py`는 같은 원본에서 1~18K 행렬과 추가 128개 합성 기준값을 생성한다. `tests/fixtures/revive_keys/provenance.json`에 출처 해시와 키별 케이스 수를 기록한다. `revive_live`와 UI 검사는 등록 1~18K의 5개 실시간 값과 홀드 미확인 표시, 희소 레인 대응, 큰 글씨 폭을 검사한다. `osu_link_boundaries`는 메모리 접근 없이 합성 `.osu` 파일을 읽어 1~18K 전체 파일 분석과 보조 계산을 연결해 확인한다.
