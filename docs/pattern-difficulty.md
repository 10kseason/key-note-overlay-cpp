# 실시간 패턴 난이도 v2.13

설정 창과 OBS 오버레이에 **실시간 난이도 / 지난 패턴 결과 / 현재 NPS**를 표시한다. NPS는 최근 1초 동안 누른 키 수이고, 난이도는 최근 8초의 입력 패턴 추정이다. 이 실시간 입력 분석은 채보 파일이나 게임 판정을 사용하지 않으므로 전체 곡의 공식 등급이나 플레이어 실력 등급은 아니다. 별도 [osu! 연동](osu-link.md)을 직접 켜면 선택 파일의 추정이 따로 표시되며, 이 기능은 기본 OFF이다. v2.12는 5K AERY의 낮은 구간에 실사용 피드백 보정을 추가하고, 10K 기준을 Revive 2026의 16코스로 교체한다. 기존 strain·10K 패턴 부담 계산·5K 원본 보정표·4K/7K/8K 기준은 유지한다.

## 키 개수별 기준

기본값은 적용된 등록 레인 개수로 선택한다. 난이도 탭의 **분석 키 수**에서 관측 입력에 따른 자동 고정 또는 4~10K 수동 고정을 별도로 선택할 수 있다. 등록 배치는 유지하며, 사용 키가 확정되면 미사용 레인을 접고 창 폭만 줄인다. [자동 고정 조건과 보류 처리](analysis-key-mode.md)를 참고한다.

| 레인 수 | 화면 단위 | 기준 |
| --- | --- | --- |
| 4K | 단위 + 높낮이 | Reform v1, 입문 1~3 · 1~10단 · α~ζ |
| 7K | 단위 + 높낮이 | Jinjin Regular, 0~10단 · γ · ψ · ζ · ★ |
| 10K | 단위 + 높낮이 | 10K Revive 2026 Skill Simulator, 1~14단 · 개전(15) · 오버조이(16) |
| 5K | AERY ⑤ | 로컬 5KEYS AERY 채보와 난이도표로 보정 |
| 8K | 단위 + 높낮이 | HeavenUsurper Regular v1, 0~10단 · Flare(11) · Aqua(12) · Life(13) · Oblatus(14) · Demise(15) |
| 나머지 | 입력 지수 /100 | 이전 자체 입력 부담 지수 |

5K 보정에는 스크래치 노트가 없는 채보를 사용했다. 8K는 네이티브 osu!mania 8키 단위 코스를 사용하며, 이전 발광 NORMAL N★ 환산과 오차 표시는 더 이상 적용하지 않는다. 이전 발광 보정 보고서는 아래에 과거 기록으로 보존한다.

## 5K AERY 보조 기준 v2.13

원래 34개 보정점과 아래의 저레벨 감소량을 보존하고, 학습용 230개 대표 채보의 잔차를 최대 ±0.5단계 범위에서 추가한다. 자료가 부족한 ⑤1~5·7은 학습용 그룹 전부, 나머지 20개 레벨은 각각 10개다. 검증용 채보는 선정에서 제외했다. 적용식·범위·작은 개선 폭과 실타건 미검증 한계는 [보조 기준 문서](aery-auxiliary-reference.md)에 기록했다. 이하 v2.12 수치 예시는 보조 적용 전의 수동 감소량 설명이다.

## 5K AERY 저레벨 보정 v2.12

사용자가 에리팩 실제 ⑤1~10 채보에서 추정값이 전반적으로 약 1단계 높다고 보고한 데 따른 수동 보정이다. 채보를 다시 학습하거나 새로운 정확도를 측정한 결과는 아니다. 원본 34개 보정점과 오프라인 검증 보고서는 보존한다.

먼저 원래 식 `L = C(strain + ln(1 + NPS8))`로 등급을 구한다. 여기에 다음 값을 적용한다.

```text
감소량 = clamp((13 - L) / 2, 0, 1)
새 등급 = max(1, L - 감소량)
```

실제 ⑤1~10이 한 단계 높게 나오면 기존 추정값은 약 ⑤2~11이므로, **기존 추정값 ⑤11 이하에 최대 -1**을 적용한다. ⑤11~13에서 감소량을 선형으로 줄이고 ⑤13 이상은 그대로 둔다. ⑤11에서 즉시 보정을 끊으면 작은 입력 차이에 등급이 한 단계 튀므로 완충 구간을 둔다. 최저 등급은 기준표의 실제 라벨 하한인 ⑤1로 제한하며 보정표 범위 밖을 나타내는 `<`/`>` 표시는 유지한다.

| 기존 추정값 | v2.12 |
| --- | --- |
| ⑤2 | ⑤1 |
| ⑤6 | ⑤5 |
| ⑤10 | ⑤9 |
| ⑤11 | ⑤10 |
| ⑤12 | ⑤11.5 |
| ⑤13 이상 | 동일 |

설정 창·HUD·연결 대기·지난 결과·새 HTML 리포트가 같은 보정값을 사용한다. 보정은 추정기에서 한 번만 적용하며 이미 저장된 HTML은 바꾸지 않는다. 5K 리포트 하단에는 `AERY 저레벨 보정 v2.12`를 표시한다. 이 5K 보정 자체는 NPS·strain·LN 추가 부담 2/3·다른 키 모드를 변경하지 않는다. 10K 기준 교체는 별도 변경이다. 오프라인 `pattern_features`의 5K 주 특징은 여전히 strain과 NPS이므로 원본 보정표 재현을 위한 특징값도 유지한다.

합성 입력의 수치 회귀, 저레벨·완충·고레벨·최저치, 결과 유지/완료, 리포트 경로를 검사한다. 전후 합성 패턴 119개 중 다른 키 모드 102개는 모든 출력이 동일했고 5K 17개는 등급 외 입력 지표가 동일했다. 수정 후 실제 플레이 정확도는 아직 재검증하지 않았다.

## 화면과 사용

- 설정의 **난이도** 탭에 큰 난이도와 NPS, 8초 평균 NPS, 2초 순간 밀도, 동시치기, 연타, 홀드 지표를 표시한다.
- 오버레이 상단은 청록색 분석, 연두색 지난 결과, 노란색 NPS의 세 칸이다. 폭 600px 이상에서는 가로 배치하며 분석·지난 결과에 같은 너비를 배정한다. 가로 배치와 설정 창의 레벨은 최대 48px 굵은 글씨를 사용한다. 긴 값은 실제 너비·높이를 재서 32px·26px·22px·기본 GUI 글꼴·13px 순으로 줄인다. 폭 600px 미만에서는 실시간·완료 레벨을 각각 30px 높이의 한 줄에 최대 26px로 표시하고 NPS는 16px 높이의 보조 줄에 표시한다. 최소 폭 240px에서도 단명·범위가 잘리지 않는지 검사한다. 크기 축소 버튼은 HUD 글자를 함께 축소하지 않는다.
- **OBS 오버레이에도 표시**를 끄고 적용하면 설정 창에서만 보인다. **입력 난이도 분석 사용**을 끄면 수집도 멈춘다.
- 처음 1.5초, 누름 8회, 서로 다른 입력 묶음 4개가 모일 때까지 `분석 중`이다. 이때도 NPS는 표시한다.
- 모든 키를 뗀 뒤 마지막 유효한 누름/뗌부터 **10초간 입력이 없을 때** `대기`로 돌아가며 결과를 확정한다. 긴 홀드도 뗀 뒤부터 10초를 기다린다. 그 전에 다시 치면 같은 측정 세션으로 이어진다.
- 짧은 휴식이나 재개 직후 표본을 모으는 동안에는 마지막 유효한 추정값을 유지하고 설정에 `연결 대기`, HUD에 `유지`를 표시한다. NPS·최근 입력 수·8초 평균 등은 현재 시각 기준으로 갱신하며, 이전 값을 새로운 측정 결과처럼 집계하지 않는다. 버퍼 손실이 발생하면 이전 추정값으로 덮어 숨기지 않는다.
- 종료 시 `완료된 패턴 · 측정 레벨`에 `7단 mid low`처럼 모드에 맞는 결과 값만 크게 표시한다. 미완료 상태는 `측정 전`이며, 좁은 HUD의 제목은 `완료`다. 세션에서 관측한 유효한 구간 중 최고 추정값을 보관하므로 종료 후 휴식 때문에 값이 낮아지지 않는다. 시작 직후에는 8초 미만의 유효 구간도 포함된다. 전체 세션 평균이나 전체 곡 등급은 아니다.
- 지난 결과는 다음 세션의 결과가 확정될 때까지 남는다. 짧은 입력이나 버퍼 손실이 있는 세션은 기존 결과를 덮지 않는다. 초기화·키 배치 변경·분석 전환·키 등록은 지난 결과도 지운다. 앱 재시작 시에는 결과를 유지하지 않는다.
- 분석 초기화, 레인 배치 변경, 분석 켜기/끄기, 키 등록 시작은 구간을 초기화한다. 외형 변경이나 저장만으로 구간을 지우지는 않는다.
- 다른 설정 탭에서의 입력, 키 등록, 테스트 노트는 표본에서 제외한다. 난이도 탭에서는 등록된 키를 버튼 조작 대신 패턴 입력으로 처리한다.

보정 범위 밖의 BMS 입력은 끝점 값에 `<` 또는 `>`를 붙인다. 범위 밖까지 수치가 정확하다는 뜻이 아니다. BMS의 `참고 ±`는 별도 채보 검증 표본의 80%가 들어온 오차 폭이며 **현재 연주의 신뢰구간이나 정확도 보장이 아니다**.

## 단위 비교와 높낮이

단순한 별점 배율 대신 선택한 실제 코스를 원래 오버레이 계산(LN 가중치 1)에 넣어 비교 기준을 만들었다. 코스마다 2초 간격의 8초 창 중 비교 부담이 가장 높은 세 창의 평균을 사용한다. 4K·7K·8K는 기존 strain, 10K는 [추가 패턴 특징을 포함한 부담](10k-pattern-model.md)을 사용한다. 실시간 값에 가장 가까운 기준을 선택하고, 인접 기준값의 중간 지점에서 단위를 바꾼다. 실시간 주 표시와 종료 결과에 같은 변환을 적용하며, 내부 ★ 값은 설정의 세부 지표에 남는다. 진행 막대는 해당 팩에서의 단위 위치다. 실시간 LN 조정은 아래와 같이 별도로 적용하며 기준 코스에는 가중치 1을 사용한다.

- **4K Reform v1**: DDMythical의 1st Pack 입문 1~3·1~5단, 2nd Pack 6~10단·Alpha~Epsilon, 3rd Pack Zeta로 구성한 19코스. Pre-v1·v2·Sample·개별 스킬팩은 섞지 않는다. [제작자 허락을 받은 Reform 보관 사이트](https://www.danreform.com/)에서 판본을 구분했다.
- **7K Jinjin Regular**: Phase I~IV의 0~10단·Gamma·Azimuth·Zenith·Stellium, 15코스. LN 전용판은 제외했다. 화면의 γ/ψ/ζ/★는 순서대로 Gamma/Azimuth/Zenith/Stellium이다. [Jinjin 제작자 게시물](https://osu.ppy.sh/community/forums/topics/449279)의 Regular 기준을 사용한다.
- **8K HeavenUsurper Regular v1**: Easy·Medium·Hard·Insane·Extreme의 0~15단, 16코스. [Easy](https://osu.ppy.sh/beatmapsets/2336219), [Medium](https://osu.ppy.sh/beatmapsets/2338305), [Hard](https://osu.ppy.sh/beatmapsets/2593505), [Insane](https://osu.ppy.sh/beatmapsets/2595237), [Extreme](https://osu.ppy.sh/beatmapsets/2596836)을 사용한다. 11~15단의 코스명은 Flare·Aqua·Life·Oblatus·Demise다. 다른 키 수 변환이나 LN 전용팩을 섞지 않는다. 기준 코스는 LN 가중치 1로 측정하고 실시간 LN 추가 부담에는 기존 2/3 조정을 유지한다.
- **10K Revive 2026 Skill Simulator**: 사용자 제공 화면의 16코스·64개 채보를 원본 BMS 해시로 고정했다. 1~14단·개전(15)·오버조이(16)이며 네 곡 사이 10초 분석용 공백으로 구간을 분리한다. 실시간 LN 추가 부담 2/3·NPS 계산은 유지하며 기준 코스는 LN 가중치 1이다. [Revive 기준 구성과 재현](revive10-reference.md)을 참고한다. 과거 Tryr 기준과 섞지 않는다.

기준 순서가 계산에서 뒤집힌 인접 코스는 평균으로 묶고 범위를 드러낸다. 현재 **4K 8~9단, 7K 3~4단, 8K 0~1·6~8·9~10·13~14단**은 이 지표로 분리하지 않는다. 8K의 Life~Oblatus 구간은 제작자 번호를 사용한 `13~14단`으로 표시하며, Flare·Aqua·Demise 단독 구간은 이름을 표시한다. Revive 10K는 16단계가 모두 분리된다. 현재 10K 수치는 [revive10-reference-report.json](revive10-reference-report.json), 4K·7K·8K와 과거 Tryr 수치는 [dan-reference-report.json](dan-reference-report.json)에 있다.

높낮이는 **`7단 low` → `7단 mid low` → `7단 수준` → `7단 high`** 네 표현이다. 한 단위의 아래쪽 경계→기준값을 0~0.5, 기준값→위쪽 경계를 0.5~1로 정규화하고 0.25 간격으로 나눈다. 따라서 정확한 기준값은 `X단 수준`이 된다. 간격이 불균등해도 중립 표현이 기준값에 맞게 유지된다. 합쳐진 단계도 `8~9단 mid low`처럼 표시한다. 최저 기준 미만/최고 기준 초과는 `입문1단↓`·`Cata단↑`처럼 알리며 그 바깥은 세분하지 않는다.

**62개 코스로 만든 비교 기준이며, 별도 보류 표본 정확도나 단위 합격 확률을 측정한 모델이 아니다.** low/high는 입력 부담의 상대 위치이고 클리어 안정도나 정확도를 뜻하지 않는다. 실제 단위는 전체 코스의 판정·체력·각 패턴 대응을 요구한다. 이 앱은 누르지 못한 노트나 게임 판정을 알 수 없으므로 **단위 클리어 인정으로 사용하지 않는다**. 상위 단위의 쉬운 부분은 낮게 표시될 수 있고, 손가락 배치·홀드 추정·타이밍 흔들림의 오차도 남는다.

## 계산 방법과 이전 버전과의 차이

v1은 모든 키 수에 같은 NPS 중심 0~100 지수를 썼다. v2는 osu!mania의 레인별 strain, 전체 strain, 홀드 간섭과 릴리즈 부담을 계산하고, BMS는 그 결과를 난이도표에 맞춘 단조 보정 곡선으로 환산한다. 단순한 키 수별 상수 배율보다 같은 밀도의 연타·교대·동시치기·홀드를 구분할 수 있고, 작은 보정 데이터에서 복잡한 모델을 과적합시키지 않도록 했다.

v2.4는 표시/세션 연결을 `LiveContinuity`에서 따로 처리한다. 종료 대기를 3초에서 10초로 늘리되, 보정에 사용한 8초 계산과 내부 3초 휴식 후 계산 재시작 규칙은 유지한다. 이 분리로 재개 직후 수치가 준비될 때까지 화면과 완료 결과가 끊기지 않으며, BMS 보정·단위 비교표를 다른 계산으로 조용히 바꾸지 않는다. 종료나 명시적 초기화 후에는 이전 세션의 추정값을 새 세션에 가져오지 않는다.

v2.5는 사용자 피드백에 따라 **LN이 추가하는 부담을 이전의 2/3**로 줄인다. 기본 타건·밀도 부담은 유지한다. `w=2/3`, 기존 홀드 간섭 계수 `h`와 릴리즈 추가값 `r`에 대해 새 입력의 키별 부담은 `2 + w×(2h−2)`, 전체 부담은 `1 + w×((1+r)h−1)`이다. 간섭·릴리즈가 동시에 생기는 교차항도 한 번만 2/3로 줄인다. 예를 들어 홀드 간섭만 있을 때 `h=1.25`에 해당하던 증가량이 `1.1667` 상당으로 내려간다.

이 조정은 최종 별점·단위 전체를 2/3로 곱하는 것이 아니다. LN 가중치만 비교하면 단타의 strain은 같고, LN 간섭이 포함된 입력은 단위/BMS 환산 **전**에 추가 부담이 줄어든다. NPS·홀드 비율·90ms 홀드 인식·10초 종료 대기는 그대로다. 기준표를 함께 낮추면 체감 조정이 상쇄되고 단타의 단계 경계도 바뀔 수 있으므로 단위·BMS 기준표는 기존 가중치 1로 유지한다. 오프라인 `pattern_features`도 명시적으로 가중치 1을 사용해 각 프로필의 현재 비교 기준을 재현한다. 10K 추가 항에는 홀드 길이를 넣지 않는다.

osu! 계산은 [ppy/osu의 고정 리비전 c752ffb](https://github.com/ppy/osu/tree/c752ffb2260abcf4dad0b7d8e298806ab9db5b24)의 `ManiaDifficultyCalculator`, `Strain`, `StrainSkill`, `IndividualStrainEvaluator`, `OverallStrainEvaluator`를 C++로 옮겨 적용했다. 레인별 감쇠 0.125, 전체 감쇠 0.30, 400ms 구간 최댓값, 내림차순 가중치 0.9, 별점 배율 0.018을 사용한다. MIT 고지는 [osu-LICENCE.txt](../third_party/osu-LICENCE.txt)에 포함했다.

실시간 계산에는 다음 차이가 있다.

- 최근 8초 구간을 평가하며, 앞선 4초의 이벤트로 strain을 예열한다. 전체 곡의 피크 분포를 사용하지 않는다.
- 실제 누름 시간의 흔들림을 줄이기 위해 첫 누름으로부터 15ms 이내의 서로 다른 레인을 동시 입력으로 맞춘다. 15ms 간격을 계속 연결하지 않으며 같은 레인 재입력은 별개다.
- 키를 90ms 미만 누르면 탭, 그 이상이면 홀드로 추정한다. 실제 채보의 LN을 알 수 없으므로 길게 누른 단타와 짧은 LN을 오인할 수 있다. 오래된 홀드 시작점이 12초 버퍼를 벗어나면 strain에 그 홀드가 온전히 반영되지 않는다.
- 실제 게임의 채보 정렬·시간 반올림·배속 모드를 그대로 재현하지 않는다. 빠르게 누른 입력은 해당 속도로 평가하지만 게임의 공식 모드별 별점과 일치한다고 보장하지 않는다.

NPS는 누름 수로 계산한다. 큰 숫자는 `(현재−1초, 현재]`의 횟수이며, 세부 지표의 8초 평균은 경과 시간으로 나누되 시작 직후 최소 2초를 분모로 쓴다. 2초 순간 밀도는 현재 구간 안에서 가장 조밀한 2초의 입력 수/2다. OS 키 자동 반복은 새 노트로 세지 않는다. 계산과 표시 갱신은 100ms 간격이며 기존 키보드 훅이 기록한 시각을 메시지 루프에서 처리한다.

지원되지 않는 키 개수에는 v1 지수를 유지하되 같은 LN 조정을 적용한다. 부담은 평균 NPS에 동시치기(0.22), 인접 입력 묶음의 250ms 미만 연타(0.75), 90ms 이상 홀드 중 추가 입력(기존 0.25 → `0.25×2/3`, 약 0.1667)을 가중하고, 평균을 넘는 순간 밀도의 0.30을 더한다. 지수는 `100 × (1 − exp(−부담 / 24))`이다. 이 값에는 게임별 난이도 단위를 붙이지 않는다.

## BMS 보정 검증 (8K는 v2.6 이전 기록)

현재 BMS 보정은 5K AERY에만 적용한다. 8K 발광 행과 보고서는 이전 버전의 검증 기록이다.

아래 수치는 **LN 2/3 및 AERY 저레벨 조정 전 기준 계산**의 검증 기록이다. v2.5 LN 조정 또는 v2.12 저레벨 보정 후의 실타건 정확도·보류 표본 오차를 다시 측정한 것은 아니다. 설정과 HUD의 `기존 보정 오차 / 기존 ±`도 이 과거 검증값을 뜻한다. 수치 회귀 통과를 실제 플레이 정확도 향상으로 해석하지 않는다.

2026-10-25 로컬에 있던 표 캐시와 채보를 읽기 전용으로 대조했다. [5KEYS AERY](https://asumatoki.kr/table/aery/header.json)와 [발광 NORMAL 난도 추정표](http://walkure.net/hakkyou/for_glassist/bms/?lamp=normal)의 MD5가 일치하는 채보만 사용했다. 표의 최신 상태를 동기화한 것은 아니다.

총 14,181개 파일을 확인해 표에 일치하는 2,011개를 추출했고, 디코딩·모드·LN 제약을 통과한 1,996개를 사용했다. RANDOM/SETRANDOM, 지뢰, 잘못된 모드, 디코더 오류, AERY의 스크래치 노트, 차지/헬차지 LN은 제외한다. AERY `+`는 0.5단계, N★의 닫힌 구간은 중간값으로 변환하며 특수·열린 등급은 제외한다.

각 곡은 8초 창을 2초 간격으로 평가한 뒤 strain이 가장 높은 세 창의 평균을 특징으로 사용했다. 같은 곡 폴더의 채보들이 학습/검증 양쪽으로 갈리지 않도록 폴더 이름 해시로 20%를 보류했다. 폴더 그룹 중복은 0이지만 다른 이름으로 복제된 곡까지 완전히 제거했다는 뜻은 아니다. 보류 표본을 사용하지 않는 4분할 교차 검증으로 밀도 가중치와 보정 곡선 구간 수를 정했다.

| 기준 | 보정 / 별도 검증 채보 | 기존 v1을 보정한 평균 절대 오차 | v2 평균 절대 오차 | 검증 오차 80% 폭 |
| --- | ---: | ---: | ---: | ---: |
| AERY 5K | 1,346 / 328 | 0.668 | 0.531 | ±1.00 |
| 발광 NORMAL N★ 8K | 277 / 45 | 1.292 | 1.254 | ±2.25 |

비교 대상 v1에도 별도의 단조 보정을 적용했다. AERY는 개선됐으나 발광은 개선 폭이 작고 검증 채보도 45개로 적다. 실제 타건 기록을 평가한 결과가 아니며, **한 곡의 강한 구간 세 개로 표 등급을 근사한 검증**이다. 모든 8초 구간이 그 곡의 등급을 가질 수는 없다. 로컬 팩 구성에 따른 편향, 판정·놓친 노트·손 배치·개인 숙련도 차이가 남는다. 수치와 특징 파일 해시는 [calibration-report.json](calibration-report.json)에 기록했다.

## 재현과 보관

오프라인 도구는 앱에 연결되지 않는다. `tools/prepare_calibration.py`는 캐시/채보 MD5를 대조하고, `tools/ExtractBmsPatterns.java`는 별도로 설치된 beatoraja의 BMS 디코더로 이벤트를 읽는다. Java 21과 디코더 JAR는 사용자가 별도 제공해야 하며 실행 파일에 포함하지 않는다. `pattern_features`는 기본 빌드 대상에서 제외되어 있다.

```powershell
python tools/prepare_calibration.py --tables <table-cache> --root <chart-root> --output build-cpp-settings/calibration/manifest.tsv
javac -encoding UTF-8 -classpath <beatoraja.jar> -d build-cpp-settings/calibration tools/ExtractBmsPatterns.java
java -Xmx512m -cp "build-cpp-settings/calibration;<beatoraja.jar>" ExtractBmsPatterns build-cpp-settings/calibration/manifest.tsv build-cpp-settings/calibration
cmake --build build-cpp-settings --target pattern_features
build-cpp-settings/pattern_features.exe build-cpp-settings/calibration
python tools/fit_calibration.py build-cpp-settings/calibration/features.tsv --header src/calibration_tables.h --report docs/calibration-report.json
```

경로 자리표시는 실제 로컬 경로로 바꾼다. 개인 경로가 든 manifest, 채보 이벤트, 표 캐시, 원본 채보, 디코더 JAR는 배포하거나 Git에 추가하지 않는다. 보정 곡선과 집계 보고서만 포함한다. 보류 표본을 보정 곡선에 다시 넣지 않는다.

아래 절차는 4K·7K·8K 및 **과거 Tryr 10K** 기준 62코스의 재현용이다. 현재 10K는 별도 [Revive 재현 절차](revive10-reference.md#재현)를 사용한다. 부족한 코스나 충돌하는 판본이 있으면 도구가 실패하며, 임의의 대체 팩을 넣지 않는다. `--root`는 여러 번 지정할 수 있다. 앱에는 원본 코스·노트 이벤트·오디오를 포함하지 않으며 다운로드 기능도 없다.

```powershell
python tools/prepare_dan_reference.py --root <course-library> --root <additional-courses> --output build-cpp-settings/dan-reference
cmake --build build-cpp-settings --target pattern_features
build-cpp-settings/pattern_features.exe build-cpp-settings/dan-reference
python tools/build_dan_reference.py build-cpp-settings/dan-reference --header src/dan_reference.h --report docs/dan-reference-report.json
python -B -m unittest discover -s tests -p test_dan_tools.py -v
```

기본 상태에서는 입력 이벤트와 지난 결과를 메모리에만 보관하며 전송하지 않는다. v2.10의 선택 옵션 `report_auto_save`를 켜면 등록된 레인의 누름·뗌 시각과 분석값을 로컬 HTML 리포트로 저장한다. 실제 키 이름·문자열·게임 창 이름은 기록하지 않는다. 기본값은 false이며 이전 설정 파일에도 꺼짐으로 적용된다. [연주 리포트의 저장 범위와 한도](session-reports.md)를 참고한다. 난이도 분석 자체는 기존과 같으며 최대 4,096개를 넘겨 최근 8초 표본 일부가 손실되면 `보류`로 알린다. JSON/INI의 `difficulty_enabled`, `difficulty_hud`는 둘 다 기본 켜짐이다. 설정은 임시 파일 기록·디스크 반영·내용 확인 후 교체하며, JSON 저장 성공과 호환 INI 갱신 실패를 구분해 안내한다.

```bat
cmake --build build-cpp-settings
ctest --test-dir build-cpp-settings --output-on-failure
```

계산 테스트는 공식 상수에 대한 작은 해석적 기준 사례, 키 모드, 레인별 연타·교대, 동시치기·홀드·릴리즈, 1초 NPS 경계, 보정 범위, 잘못된 입력·버퍼 제한과 결과 확정/유지를 확인한다. 단위 기준점·중간 경계·네 높낮이·합쳐진 범위·10K BMS 개별 단계와 5K 보정 분리도 검사한다. 10K 조합 변화·리듬 흔들림 허용·좌우 반전·초기 표본·반복 부담과 LN 조정도 검사한다. Python 검사는 원본 메타데이터 선택, 탭/LN 파싱과 역전 범위 합치기를 확인한다. 숨겨진 네이티브 UI 테스트는 가운데 문구, 최소 폭, 6줄 세부 지표, 잠긴 JSON·읽기 전용 INI·저장 재시도·잘린 JSON 복원과 입력 제외 경로를 검사한다. 데스크톱을 캡처하지 않고 앱의 자체 HUD를 비트맵으로 그려 가로·세로 배치를 확인한다. 실제 키보드·게임·OBS·다른 화면 배율의 시각적 확인은 별도로 필요하다.

## 2026-10-28 보조 표시

1~18K는 [Revive CPP 보조지표](revive-cpp-auxiliary.md)를 별도로 갱신한다. 타건 기반 6개 특징을 계산하며 170ms 이상 누른 입력을 홀드(LN)로 추정한다. 170ms 미만은 단타, 해당 홀드 입력이 없으면 홀드 0이다. 누르고 있는 중에도 170ms부터 반영하며 채보 파일의 실제 LN 판정은 변경하지 않는다. 이 변경은 CPP 보조지표에만 적용하며 위 주 난이도 추정과 4K LN 비교의 입력 추정 방식은 유지한다. 4K는 일반 Reform 기준에 더해 [4K LN v2 1~15단 비교](ln4-reference.md)를 표시한다. 주 난이도 수식은 유지하고 기준을 합산하지 않는다. HUD 제목은 `보조지표`이며 스킬 이름 22px, 수치 26~32px, 4K LN 수치 최대 32px를 사용한다. 좁은 칸은 이름과 값을 두 줄로 나누고, 모든 스킬 칸과 노트 영역이 보이도록 필요한 표시 높이를 확보하며 저장 크기는 유지한다.
