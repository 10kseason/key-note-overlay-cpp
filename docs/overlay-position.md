# 마우스 이동과 위치 저장

v2.11에서는 실행 직후 설정 창을 표시하기 전에 오버레이와 겹치지 않는 위치를 찾는다. 오버레이가 있는 모니터의 작업 영역에서 아래·오른쪽·왼쪽·위쪽과 모서리를 확인하고, 필요하면 다른 모니터를 찾는다. 작업 표시줄 영역을 피하며 음수 모니터 좌표도 처리한다. 저장된 오버레이 위치·크기는 유지하고 설정 창 위치만 정한다. 모든 화면에 두 창이 들어갈 공간이 없으면 화면 안에서 겹침이 가장 작은 후보를 쓴다. 설정 창이 화면 자체보다 큰 저해상도·배율 조합의 UI 축소는 이번 변경 범위에 포함하지 않는다.

설정 **위치 · OBS → 마우스로 위치 이동**, 또는 트레이 우클릭 **오버레이 마우스로 이동**을 선택한다. 오버레이를 잡아 끌고 놓으면 좌표가 자동 저장된다. 원하는 위치에 놓은 뒤 같은 버튼/메뉴로 이동 모드를 끈다. OBS 모드에서 클릭 통과를 꺼 둔 경우에는 평소에도 보이는 오버레이 영역을 직접 잡아 옮길 수 있다. 게임용 모드는 항상 클릭을 통과시키므로 이동 모드로 배치한다.

이동 모드에서는 클릭 통과를 잠시 해제하고 배경·테두리·안내를 표시한다. 투명색 픽셀은 마우스 입력을 받지 못하기 때문에 임시 배경이 필요하다. 이 표시는 OBS에도 보일 수 있으므로 배치가 끝나면 이동 모드를 끈다. 기존 클릭 통과·배경 설정은 변경하지 않으며 다음 실행은 이동 모드가 꺼진 상태로 시작한다. 창을 다시 만들지 않아 OBS 캡처 대상도 유지된다.

좌표를 직접 입력하고 **위치 저장**을 눌러도 된다. **이 모니터 중앙으로 → 위치 저장**은 화면 밖의 오버레이를 돌아오게 한다. 음수 X/Y는 왼쪽·위쪽 모니터 위치로 저장할 수 있다. 현재 설정 파일의 기존 `overlay.x`, `overlay.y`를 사용해 다음 실행에 복원하며 새 파일 형식은 추가하지 않는다. 모니터 구성이 바뀌었을 때 자동으로 재배치하지는 않는다.

자동 저장과 **위치 저장**은 마지막 저장 설정 위에 X/Y만 갱신한다. 다른 탭의 미적용 편집, 잘못 입력된 값, 적용했지만 아직 저장하지 않은 값은 그대로 남는다. 모든 설정을 저장하려면 기존 **적용 + 저장**을 사용한다. 저장 실패 시 이전 파일을 유지하고 실패를 안내하며, 현재 위치를 **위치 저장**으로 다시 시도할 수 있다. JSON만 성공한 경우 호환 INI 갱신 실패를 구분해 알린다.

Windows의 기본 창 이동 루프(`HTCAPTION`, `WM_ENTERSIZEMOVE`, `WM_EXITSIZEMOVE`)를 사용한다. 새 전역 단축키·마우스 훅·서비스를 추가하지 않는다. 실제로 위치가 바뀐 사용자 이동이 끝날 때만 저장한다. 프로그램의 창 배치, 움직이지 않고 놓기, Esc 취소로 원위치로 돌아온 경우는 자동 저장하지 않는다.

`overlay_settings_workflow`는 숨겨진 실제 창과 별도 설정 파일로 초기 설정 창 배치 시 오버레이 설정 보존, 클릭 통과 임시 해제/복원, 음수 좌표, JSON/INI 재로드, 위치만 저장, 다른 미저장 편집 유지, 잠금에 의한 실패와 재시도, 취소/무이동 경로를 검사한다. `game_overlay_native`에는 1080p·1440p·화면 하단 오버레이·음수 좌표 모니터·다른 모니터로 배치·공간 부족의 배치 계산 검사가 있다. 마우스 입력을 주입하지 않는 검증이므로 실제 마우스 드래그, 다중 모니터·서로 다른 DPI에서의 사용과 OBS 캡처는 별도 실사용 확인이 필요하다.
