# 연주 리포트 v2.12

10K는 Revive 2026의 1~14단·개전(15)·오버조이(16) 기준으로 새 리포트를 작성한다. 하단에 기준 버전을 표시하며 과거 HTML은 그대로 보존한다. [기준과 한계](revive10-reference.md)를 참고한다.

## 사용

설정 **난이도 → 연주 리포트 자동 저장 (레인·타이밍 포함, 로컬 HTML) → 적용 + 저장**을 누른다. 기본값은 꺼짐이다. 체크만 한 편집 상태는 수집을 시작하지 않으며, 적용한 뒤 새 연주부터 기록한다. 분석 자체가 꺼져 있으면 리포트도 수집하지 않는다.

등록된 레인을 누르면 시작하고, 모든 키를 뗀 뒤 마지막 누름/뗌으로부터 10초가 지나면 완료한다. 10초보다 짧은 휴식은 같은 연주로 이어진다. 설정 파일이 있는 폴더 아래 `reports`에 고유 이름의 HTML을 만들며 **리포트 폴더 열기**로 찾을 수 있다. 해당 폴더가 쓰기 가능한 위치여야 한다. 앱을 켤 때나 저장 옵션이 꺼져 있을 때에는 폴더를 만들지 않는다.

키 배치 변경, 분석·리포트 옵션 변경, 키 등록 시작, 분석 초기화는 진행 중 기록을 마무리한다. 정상 종료도 진행 중 기록을 저장한다. 이때 잡고 있던 키는 종료 시점에서 닫고 타임라인에 노란색으로 구분한다. 외형만 바꾸는 적용은 같은 세션을 유지하지만 기존 앱 동작대로 눌린 키 상태가 초기화되므로 해당 홀드를 표시한다. 저장 옵션을 끄면 그때까지의 기록은 저장하고 이후 입력은 수집하지 않는다. 이미 만들어진 리포트는 자동 삭제하지 않는다.

## 리포트 내용과 해석

- 연주 길이: 첫 누름부터 마지막 뗌까지. 끝의 10초 대기 시간은 제외한다.
- 총 누름과 평균 NPS: OS 자동 반복을 제외한 누름 수. 전체 평균에는 연주 중 휴식이 포함되며, 1초 미만 연주는 분모를 1초로 사용한다.
- 최대 1초 NPS: 보존한 타건 시각에서 `(t−1초, t]`의 최대 누름 수를 계산한다. UI 관측 간격 때문에 짧은 버스트를 놓치지 않도록 별도로 계산한다.
- 시간별 NPS·난이도 그래프: 약 0.5초 간격 관측값. 1초를 넘는 관측 공백은 선을 잇지 않는다. 난이도 준비 중·연결 대기용 유지 값·분석 버퍼 초과 구간도 연결하지 않는다. 점에 마우스를 올리면 시각과 등급을 볼 수 있다.
- 난이도 세로축: 4K·7K·8K는 구간 strain 환산값, 10K는 패턴 비교 부담, 5K는 AERY ⑤, 다른 키 수는 입력 지수다. 단위명은 점의 설명과 최고 구간 표에서 확인한다. 다른 키 수끼리 숫자를 비교하지 않는다.
- v2.12에서 새로 생성하는 5K 리포트는 화면과 같은 AERY 저레벨 보정값을 사용하고 하단에 보정 버전을 표시한다. 기존 추정값 ⑤11 이하에서 최대 1단계를 낮추고 ⑤13까지 보정량을 줄인다. 이미 저장된 HTML은 변경하지 않는다. [계산식](pattern-difficulty.md#5k-aery-저레벨-보정-v212)
- 최고 구간: 유효한 관측 중 가장 높은 난이도와 직전 최대 8초 구간, 그때의 동시치기·연타·홀드 겹침 비율. 평균 곡 난이도나 클리어 판정은 아니다.
- 레인별 타임라인: 오버레이 왼쪽부터 L1, L2…로 표시하며, 실제 키 이름은 기록하지 않는다. 짧은 누름은 점처럼, 90ms 이상 홀드는 길이로 표시한다. 가로 스크롤과 막대 설명으로 시각을 확인한다.

연주 리포트는 곡명, 채보 파일, 게임 판정, 놓친 노트, 개인 손 배치·체력을 사용하지 않는다. 별도 [osu! 선곡 연동](osu-link.md)을 켜도 그 채보 정보가 연주 리포트에 들어가지는 않는다. 실제 누른 입력만 분석하므로 누락·무관한 타건도 결과에 영향을 준다. 리포트는 실시간 입력 화면과 같은 난이도·보정·LN 추가 부담 2/3를 사용한다.

## 저장 범위와 실패 처리

HTML에는 컴퓨터의 로컬 시작 시각, 키 수, 레인 번호·상대 타이밍, 분석값이 포함된다. 실제 키 코드·이름·입력 문자열·활성 창 제목·사용자 경로를 넣지 않는다. OBS 모드에서는 등록 키가 게임 외 프로그램에서도 관측될 수 있으므로 필요한 동안만 켠다. v2.11의 [게임용 모드](game-overlay.md)는 osu!·Qwilight가 앞에 있을 때와 설정의 난이도 탭 연습으로 새 타건을 제한한다. 키 배치 등록과 애니메이션 테스트는 제외한다.

네트워크 전송·외부 JS·외부 글꼴이 없는 독립 HTML이다. `reports/`는 Git에서 제외하며 배포 패키지에도 넣지 않는다. 공유 여부는 사용자가 결정한다. `examples/session-report-demo.html`은 자동 검사에서 만든 합성 입력 예시다.

파일 생성은 기존 입력 처리와 분리된 일회성 저장 작업에서 실행한다. 임시 파일을 완전히 기록·flush한 뒤 같은 폴더에서 이름을 바꾼다. 기존 파일을 덮어쓰지 않으며 실패 시 임시 파일을 정리한다. 서비스·시작 프로그램·항상 실행되는 별도 프로세스는 추가하지 않았다.

저장 실패는 난이도 탭에 표시하며 원본 기록을 메모리에 유지한다. 폴더 권한·디스크 공간을 확인하고 **저장 재시도**를 누른다. 미저장 리포트 4개가 쌓이면 새 수집을 일시 중지한다. 복구한 뒤에는 10초간 입력을 멈추고 새 연주를 시작하거나 분석 초기화를 누른다. 정상 종료 중 실패하면 **미저장 리포트를 버리고 종료 / 돌아가서 재시도**를 선택한다. 강제 종료·충돌·운영체제 강제 종료 시 미저장 메모리 기록의 복구는 보장하지 않는다.

한 연주에서 타건 50,000개, 그래프 관측 7,200개(연속 관측 약 1시간)를 보관한다. 초과하면 앞부분을 보존하고 리포트에 기록 제한을 표시한다. 누름 합계와 최고 난이도 관측은 계속 갱신하지만 최대 NPS는 보존된 타건 기준이므로 전체 최고치보다 낮을 수 있다. 난이도 분석 버퍼 자체가 초과되면 최고 난이도는 보류한다. 한도가 있는 것은 장시간 입력이나 저장 실패로 메모리가 무한히 늘어나는 것을 막기 위해서다.

## 검증

`session_report_test`는 세션 경계·홀드·자동 반복 제외·보존된 난이도 제외·상한·HTML 이스케이프·독립 파일 구성·한글 경로·충돌 없는 새 파일·실패 반환을 검사한다. 숨겨진 네이티브 UI/종료 검사는 기본 꺼짐, 적용 전 미수집, JSON/INI와 이전 설정, 자동 저장, 늦은 타이머, 중복 방지, 미저장 큐 한도, 실패·재시도, 옵션 해제와 종료 저장을 검사한다.

실제 게임·OBS 캡처·다른 PC에서의 동작과 브라우저 화면은 별도 확인이 필요하다. 개발 환경의 브라우저 정책이 로컬 HTML 열기를 차단해 렌더링 시각 검증은 수행하지 못했다. 자동 검사는 이를 대신하지 않는다.

2026-10-26 v2.10 배포 UI 검사의 일회성 종료 코드 3을 후속 조사했다. 첫 리포트 저장이 실패했을 때 없는 폴더를 읽는 예외가 검사 밖으로 빠져나가 동일한 종료를 만드는 경로를 재현했다. v2.11은 폴더 순회의 생성·증가 및 정리 오류를 검사 실패로 반환하고, 예상하지 못한 자체 검사 예외도 진단 로그와 종료 코드 2로 처리한다. 첫 저장을 강제로 막고 데이터 보존·폴더 읽기 오류·재시도까지 검증한다. 최초 사고 때 실제로 저장이 실패했는지는 증거가 없어 확정하지 않았다.
