# 분석 키 수 고정

2026-10-27 로컬 변경. 키 배치·키 표시와 난이도 분석 기준을 분리한다. 기존 strain, 패턴 부담식과 LN 가중치는 유지한다. 2026-10-28의 [Revive CPP 보조값](revive-cpp-auxiliary.md)은 등록 배치/분석 기준이 1~18K일 때 최근 8초 입력에 적용하며, osu! 원본 1~18K 선택 파일의 전체 분석과 구분한다. 실시간 보조지표는 170ms 이상 누른 입력을 홀드(LN)로 추정해 6개 특징을 표시한다. 선택 채보 보조지표는 입력 시간 제한 없이 파일의 실제 LN을 사용한다. 4K 분석 기준에는 일반 Reform과 별도로 [4K LN v2 비교](ln4-reference.md)를 표시한다.

## 사용

난이도 탭의 **분석 키 수**를 고르고 **적용** 또는 **적용 + 저장**한다.

| 선택 | 동작 |
|---|---|
| 등록 키 수 (기존) | 기본값. 등록 레인 수에 해당하는 기존 기준을 쓴다. |
| 자동 추정 · 세션 고정 | 실제 눌린 등록 키를 관찰한 뒤 4~10K 중 하나로 고정한다. |
| 4K~10K 수동 고정 | 선택한 분석 기준을 사용한다. 일부 키만 누르는 구간에도 바뀌지 않는다. |

예를 들어 10개 키를 등록한 채 그중 4개를 사용하면, 자동 또는 4K 고정으로 Reform 기준을 사용할 수 있다. 등록한 키·색상·개별 설정과 입력 수집은 유지한다. 사용 키가 확정되면 아래 규칙으로 화면의 미사용 레인만 접는다. 분석 수보다 적은 키만 등록한 수동 설정도 허용하므로, 올바른 기준 선택은 사용자에게 달려 있다.

## 확정된 레인 접기

- **등록 키 수 (기존)**에서는 전체 배치를 계속 표시한다.
- 자동 추정 중에는 전체 레인을 표시한다. 키 수가 확정되면 실제 사용한 키만 원래 등록 순서대로 모아서 표시한다.
- 수동 고정은 실제 관측 키가 설정한 수와 같고, 각 키를 두 번 이상 눌렀을 때 접는다. 단순히 앞쪽 N개 레인을 선택하지 않는다. 사용 키가 아직 부족하면 전체를 유지한다.
- 레인 폭·간격, 노트 크기·색·키 이름·롱노트는 유지한다. 왼쪽 위 위치와 저장 크기는 유지한다. 실제 높이는 접힌 폭에서 모든 HUD 항목과 노트 영역을 표시할 수 있도록 필요한 만큼 확보한다. 난이도 HUD를 위해 최소 가로 폭은 240px다.
- 잠깐 일부 키를 사용하지 않거나 연주가 끝나도 접힌 배치는 유지한다. 10초 무입력 뒤 새 연주를 시작하면 다시 전체를 표시하며 관찰한다.
- 추가 키로 고정 수를 넘기면 전체 레인을 다시 펼치고 분석은 보류한다. 분석 초기화·분석 끄기·키 등록 모드에서도 전체를 표시한다.
- 설정의 가로 폭은 **펼친 전체 배치의 폭**이다. 접힌 실제 창 폭으로 설정 파일을 덮어쓰지 않는다. 분석·리포트에는 원래 물리 레인 번호를 그대로 사용한다.

OBS 창 캡처 소스의 실제 가로 크기도 바뀔 수 있다. OBS에서 크기 맞춤·자르기를 고정해 두었다면 실제 사용 환경에서 확인해야 한다.

6K·9K는 이 앱에 단위 보정표가 없어 기존 `/100` 입력 지수를 유지한다. 설정 변경은 분석과 진행 중 리포트의 구간을 구분하며 새 기준으로 다시 시작한다. osu! 파일 분석·연동의 채보 키 수에는 이 설정을 적용하지 않는다.

## 자동 고정 규칙

- 유효한 등록 키의 누름·뗌만 사용한다. OS 키 반복, 테스트 노트, 키 등록 작업, 제외되는 설정 입력은 추정에 넣지 않는다.
- 첫 누름부터 최소 8초, 누름 32회, 서로 다른 관측 키 4~10개가 필요하다.
- 관측한 모든 키를 두 번 이상 눌러야 하며, 마지막으로 새로운 키를 관측한 뒤 3초가 지나야 한다.
- 확정 전에는 `키 추정 중`과 현재 NPS를 표시하고 난이도 결과를 내지 않는다.
- 확정 후 같은 세션에서는 키 수를 늘리거나 줄이지 않는다. 사용 키가 적은 구간에서도 기준을 유지한다.
- 확정한 수보다 많은 키가 관측되면 `키 수 확인`으로 보류한다. 실제 입력과 NPS는 유지하되 해당 세션의 최고 난이도는 확정하지 않는다. 자동 리포트에도 원인을 기록한다.
- 모든 키를 놓고 마지막 입력부터 10초가 지난 뒤 새 누름이 들어오면 새 세션에서 다시 추정한다. 홀드를 계속 누르는 시간은 무입력 종료로 취급하지 않는다. **분석 초기화**로도 다시 추정한다.

이는 관측한 키 수의 추정이다. 예를 들어 7K 채보의 앞부분에서 4개 키만 충분히 사용하면 4K로 잠정 고정될 수 있으며, 뒤늦게 다른 키가 나오면 보류한다. 쓰지 않은 키의 존재는 타건만으로 알아낼 수 없다. 정확한 모드를 알고 있을 때는 수동 고정이 가장 예측 가능하다.

수동 고정에서도 한 세션에서 관측한 키가 설정 수를 넘으면 보류한다. 키를 잘못 눌렀거나 다른 키 모드로 바꿨다면 분석 초기화, 10초 뒤 새 연주, 또는 설정 변경으로 새 세션을 시작한다.

## 저장과 리포트

INI의 `[overlay] analysis_key_mode`, JSON의 `overlay.analysis_key_mode`에 같은 정수를 저장한다.

- `0`: 기존 등록 키 수 기준. 이전 설정 파일에 항목이 없거나 값이 잘못됐을 때도 이 기본값을 쓴다.
- `-1`: 자동 추정.
- `4`~`10`: 수동 고정.

자동 추정의 관측 기록과 고정 결과는 설정에 저장하지 않는다. 재시작하면 다시 관찰한다. 자동 리포트는 기존처럼 기본 OFF이며, 활성화하면 등록 레인 타이밍을 그대로 기록하고 분석 기준이 다르면 두 키 수를 구별해 표시한다. 저장된 과거 리포트는 변경하지 않는다.

## 확인 범위

합성 입력으로 자동 고정·축소 방지·늦은 추가 키 보류·홀드/키 반복·10초 새 세션, 수동 기준 변경, 희소 레인 번호, NPS 보존을 검사한다. 접기 전후 레인 간격·폭과 물리 키 대응, 최소 창 폭, 새 키 감지 시 펼침도 검사한다. 네이티브 숨김 창과 자체 렌더링 픽셀로 실제 창 폭·색상·노트 폭·롱노트 경로를 확인한다. 기존 난이도·기준표 검사와 설정 저장/복원, HTML 리포트의 기준 표시도 검사한다. 실제 게임·OBS 장시간 사용과 사용자의 키보드에서는 별도 확인이 필요하다.

보조지표는 등록 1~18K에서 각 키 수의 원본 일반 배치 행렬을 사용한다. 1~3K·11~18K는 직접 키를 등록하고 `등록 키 수 (기존)`을 선택한다. 수동/자동 선택 범위는 기존 4~10K다. 큰 배치의 일부 키를 수동/자동 기준으로 쓰면 해당 수의 레인이 모두 관측된 뒤 등록 순서로 대응한다. 일부 키가 최근 창에서 사라져도 대응은 유지하고, 추가 키는 지표를 보류한다. 등록 키 수와 분석 키 수가 같으면 모든 키를 눌러야 하는 추가 조건이 없다.
