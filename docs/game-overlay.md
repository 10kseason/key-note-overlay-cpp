# osu! · Qwilight 게임 오버레이 v2.12

## 사용

1. 실행 후 **키 배치**에서 게임과 같은 키를 등록한다.
2. **위치 · OBS → 게임용 모드 (osu! · Qwilight 입력 / 항상 표시) → 적용 + 저장**을 누른다.
3. **마우스로 위치 이동**을 켜서 위치를 잡고 이동 모드를 끝낸다. 게임이 앞에 있지 않아도 표시를 유지한다.
4. 설정 창을 최소화하고 게임으로 돌아간다. 설정 창을 닫으면 앱 전체가 종료된다. 다시 열 때는 트레이 아이콘을 사용한다.
5. 리포트가 필요하면 **난이도 → 연주 리포트 자동 저장**도 별도로 켜고 저장한다.

게임용 모드와 리포트는 기본 꺼짐이다. JSON의 `overlay.game_overlay` 또는 INI의 `game_overlay`로 저장한다. 이전 설정에는 항목이 없어 OBS 모드로 시작한다. 새 전역 단축키나 시작 프로그램은 추가하지 않는다.

## 게임과 창 모드

- osu! stable/lazer: `osu!.exe`, `osu.exe`를 인식한다. 창 모드 또는 테두리 없는 전체 화면을 사용한다. 독점 전체 화면에서는 다른 앱의 창을 덮어 그릴 수 없다.
- Qwilight: `Qwilight.exe`를 인식한다. 공식 코드의 창 모드는 일반 창, 전체 화면은 테두리를 없앤 최대화 창이다. 이 창 위에 독립 오버레이를 배치하도록 구성했다.
- 실행 파일명은 대소문자를 구분하지 않고 정확히 비교한다. 이름이 다른 사용자 빌드·런처·다른 게임은 자동 인식하지 않는다. 실행 파일명은 호환성 판별이며 보안 인증은 아니다.

Qwilight의 창 구현 근거: [MainWindow.SetWindowedMode, commit 6d3887f](https://github.com/thenist/Qwilight/blob/6d3887f6688a1f97c1fbe2bffd28feaedc9920b6/Qwilight/View/MainWindow/MainWindow.xaml.cs). 해당 코드 확인은 실제 Qwilight 플레이 검증을 대신하지 않는다.

## 표시와 입력

게임용 모드에서는 항상 위·클릭 통과·포커스 비활성 창을 사용한다. v2.12부터 캡처 선택 대상이 될 수 있도록 일반 앱 창 스타일을 유지한다. 위치 확인용 배경은 숨기고, 이동 모드에서만 클릭을 받아 드래그한다. 게임이 자기 창을 올리는 경우를 위해 500ms 간격으로 오버레이 순서를 다시 올린다. 게임 창의 위치·스타일·설정은 변경하지 않는다.

다른 앱으로 전환해도 오버레이 표시와 항상 위 상태를 유지한다. Discord나 OBS를 선택했을 때 창을 숨기던 v2.11 동작을 제거했다. 다른 앱의 새 입력은 분석·리포트에 추가하지 않는다. 전환 당시 눌린 키는 닫아서 홀드가 남지 않게 한다. 게임 안의 메뉴·채팅과 실제 플레이는 구분하지 않으므로 등록된 키를 누르면 수집될 수 있다. 설정의 **난이도** 탭 연습은 허용한다. 게임이나 모드를 바꿀 때 완전히 별도 기록이 필요하면 분석 초기화를 사용한다. 10초 미만의 짧은 전환은 기존 세션에 이어질 수 있다.

이 수정은 독립 오버레이 창이 숨겨지지 않게 하는 것이다. Discord에서 **osu!/Qwilight 게임 창만 공유**하면 별도 오버레이가 자동 합성되지 않는다. 게임과 오버레이만 함께 내보내려면 OBS에서 두 창을 합성한 화면을 공유해야 한다. 실제 Discord 캡처 목록·전송 결과는 별도 확인이 필요하다.

이 게임용 모드 자체는 전경 창의 프로세스 실행 파일 경로만 조회하고 잠시 캐시한다. 창 제목, 게임 메모리, 채보, 판정은 읽지 않으며 프로세스 경로를 리포트에 저장하지 않는다. 별도 **osu! 연동** 옵션을 직접 켠 경우에만 메모리에서 채보를 식별하고 파일을 분석한다. 해당 옵션은 기본 OFF이며 [별도 위험 안내](osu-link.md)를 따른다. 기존 키보드 훅은 입력을 다음 훅으로 전달한다. DLL 주입·입력 재전송·게임 렌더러 수정은 없다.

Win32 근거: [계층 창과 마우스 통과](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows), [SetWindowPos의 HWND_TOPMOST와 SWP_NOACTIVATE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos).

## 확인과 문제 해결

게임 위에 보이지 않으면 창 모드를 먼저 확인하고, **마우스로 위치 이동**으로 오버레이가 화면 안에 있는지 확인한다. 다른 권한 수준으로 실행한 게임의 프로세스 조회가 거부되면 입력을 인식하지 못할 수 있다. 두 앱을 일반 사용자 권한으로 실행하는 구성을 우선 사용한다. 일반 OBS 창 캡처에도 게임용 모드를 사용할 수 있다. 입력이 없으면 움직이는 노트가 사라지는 것은 정상이며, 창 자체는 계속 유지된다.

자동 검사는 실제 숨겨진 별도 프로세스를 `osu!.exe`, `osu.exe`, `Qwilight.exe`, `Quaver.exe`라는 테스트 파일로 만들어 Windows 프로세스 조회와 제외 규칙을 확인한다. 실제 게임을 실행하거나 수정하지 않는다. 숨겨진 오버레이에서는 topmost·click-through·no-activate·APPWINDOW·캡처 제외 없음·게임 밖 전환 시 스타일 유지·이동 모드·OBS 복귀·홀드 해제·JSON/INI 저장을 검사한다. 초기 창 배치 검사도 포함한다.

실제 osu!/Qwilight 플레이, 게임별 전체 화면 전환, OBS 캡처, 관리자 실행 조합, 다른 PC·DPI·모니터에서의 동작과 입력 지연은 아직 확인하지 않았다.
