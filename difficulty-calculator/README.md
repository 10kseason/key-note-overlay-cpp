# 채보 난이도 계산기 v0.1.0

채보 파일을 읽어 전체 요약, 시간별 난이도 비교값과 NPS를 보여주는 별도 Windows 데스크톱 앱이다. 오버레이를 실행하지 않아도 되며 게임·키보드 입력·화면을 감시하지 않는다. 오디오·BGA·이미지를 열거나 재생하지 않고, 네트워크 통신과 자동 저장도 없다.

## 사용

1. 배포 폴더의 `ChartDifficultyCalculator.exe`를 실행한다.
2. **채보 열기…**에서 `.osu`, `.bms`, `.bme`, `.bml` 하나를 선택한다.
3. 가장 강한 구간의 요약과 두 그래프를 확인한다. 그래프에 마우스를 올리면 해당 구간의 등급·NPS가 표시된다.
4. 필요할 때만 **HTML 리포트 저장…**을 누른다. 원본 절대 경로는 저장하지 않지만 곡명·제작자·채보명은 포함하므로 공유 전에 확인한다.

파일 읽기와 분석은 별도 작업 스레드에서 실행한다. 분석 중에는 파일 변경·저장·모드 변경을 잠시 막고 진행 상태를 표시한다. 실패하면 사유를 표시하고 잘못된 결과를 남기지 않는다. 실행 파일에 채보 경로 하나를 인자로 넘겨서 열 수도 있다.

## 난이도 해석

오버레이 v2.13의 소스 계산기를 직접 공유한다. 5K는 AERY 저레벨 보정과 보조 기준 230채보를 사용한다. 이 표본은 전체 200개 폴더 그룹에서 왔으며 같은 곡의 다른 난이도가 서로 다른 레벨의 대표가 될 수 있다. 기존 34개 기준점을 유지하고 보조 보정은 ±0.5레벨 이내로 제한한다. 10K는 Revive 2026의 1~14단·개전(15)·오버조이(16), 4K·7K·8K는 기존 단위 기준을 사용한다. 다른 키 수는 참고 입력 부담 `/100`이다. 보조 기준의 선정·부족한 레벨·검증 한계는 배포의 `docs/aery-auxiliary-reference.md`에 있다.

- **요약:** 첫 노트부터 입력을 재생해 실시간과 동일한 `DifficultyEstimator`, `LiveContinuity`, `PatternSummary`를 사용한다. 최근 최대 8초 창을 0.1초마다, 각 누름 직전과 파일 끝에도 계산하고 유효한 최고 구간 하나를 표시한다. 이전의 2초 간격 상위 3개 평균은 사용하지 않는다. 준비 조건과 휴식 중 표시 유지도 실시간과 같으며, 유지된 값은 새 최고값으로 세지 않는다. 긴 휴식으로 입력 세션이 나뉘어도 파일 전체의 최고 구간을 보존한다. 표본이 부족하거나 어느 구간이든 분석 버퍼가 초과되면 요약을 보류한다.
- **NPS:** 그래프는 0.1초마다, 그리고 파일 끝 시점에 관측한 최근 1초의 노트 수다. 상단의 최대 NPS는 전체 노트 시각에서 1초 이동 구간을 직접 계산하므로 그래프 표본 사이의 순간 최고값도 포함한다. 누름 직전의 최고 난이도는 그래프 표본 사이에 있을 수 있다.
- **길이:** 첫 노트부터 마지막 노트의 끝까지다. 단타에는 입력 모델의 10ms 릴리즈를 사용한다. 오디오 파일의 재생 길이는 아니다.
- **오버레이와 공유하는 계산:** 기본값으로 LN 추가 부담에 2/3을 적용한다. 키 수는 파일에 명시된 값을 사용한다. 기존 파일 결과·기준표 재현을 위해 파일 재생은 90ms 홀드 정책을 유지하며, 오버레이 v2.16.2부터 물리 타건의 LN 추정은 170ms다. 실제 타건의 누락·누름/뗌 시각과 UI 타이머 지연도 파일 재생과 달라 실타건 숫자까지 항상 일치하지는 않는다. 파일 분석의 타이머는 첫 노트에 맞춘다.
- **기준 채보 측정:** 기존 선택 옵션으로 LN 추가 부담만 1로 바꾼다. 요약은 동일한 최고 구간 방식이므로 과거 기준 생성 도구의 상위 구간 평균과는 다르다. 선택을 바꾸면 같은 파일을 다시 분석한다. 배속을 변경하는 옵션은 없다.

**요약은 공식 곡 등급, 플레이어 실력, 단위 합격 확률이 아니다.** 최근 구간의 패턴 부담을 기준 채보와 비교한 추정이며, 네 곡 코스의 체력·게이지·판정·실수는 모델링하지 않는다. 5K에서는 보정된 구간 등급, 4K·7K·8K에서는 strain, 10K에서는 패턴 부담의 최고 구간을 해당 단위로 표시한다. 서로 다른 키 수의 그래프 숫자를 직접 비교하지 않는다.

## 지원 범위와 오류 처리

- osu!mania `Mode:3`, 1~18K의 단타·홀드. osu!standard/taiko/catch는 거부한다.
- 스크래치 없는 BMS 5K/10K: 두 손의 키 채널, 일반·확장 BPM, STOP, 마디 길이, LNOBJ, LN 채널 및 CN을 처리한다. PLAYER 3의 한쪽 손이 비어 있어도 10K로 유지한다.
- CN은 물리적인 누름·홀드·뗌으로 읽으며 릴리즈 판정과 게이지는 모사하지 않는다.
- RANDOM/분기, HCN, 지뢰, 스크래치, 7K/14K BMS 추가 레인, 지원하지 않는 타이밍 확장, 같은 레인의 모순된 중첩은 설명과 함께 거부한다. 소리·이미지 채널은 읽지 않는다.
- 최대 파일 32MiB, 20만 노트, 2시간. 계산 모델의 최근 8초 입력 버퍼가 넘치면 요약을 보류한다.
- UTF-8과 CP932(Shift-JIS) 메타데이터를 처리한다. UTF-16은 거부한다. CP949 등 다른 인코딩은 제목이 잘못 보일 수 있으므로 UTF-8 사본을 사용하는 것이 좋다. 원본은 앱에서 변경하지 않는다.

실제 10K Revive 64개 채보의 노트 수·레인 순서를 기존 독립 디코더 결과와 대조했다. 총 102,300개 노트가 일치했고, 실수 시각을 유지하는 새 파서와 기존 정수 ms 출력 사이의 최대 차이는 1.121486ms였다. 부동소수 계산·정수 절삭 차이가 포함될 수 있지만 정확한 원인은 단정하지 않는다. 완전한 BMS 디코더 호환성이나 실제 난이도 정확도 검증을 의미하지 않는다.

## 빌드와 검사

Windows, CMake 3.20+, Ninja, C++17 컴파일러가 필요하다. `build_calculator.bat`를 실행하거나 다음 명령을 사용한다.

```powershell
cmake -S difficulty-calculator -B difficulty-calculator/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=<g++-path>
cmake --build difficulty-calculator/build --parallel 4
ctest --test-dir difficulty-calculator/build --output-on-failure
```

소스 빌드는 부모 프로젝트의 `src` 계산기를 사용하므로 이 폴더와 부모 소스를 함께 보관한다. CMake가 공유 `.cpp`를 빌드 폴더에 복사하는 것은 MinGW의 비ASCII 외부 소스 오브젝트 경로 문제를 피하기 위함이다. 원본이 변경되면 CMake가 재구성한다. 실행 파일은 단독 실행 가능하며 Java/JAR·원본 팩이 포함되지 않는다.

`--self-test [preview.bmp]`는 숨겨진 자체 창에서 합성 파일의 비동기 읽기·분석·모드 변경·버튼 상태를 확인한다. 선택 인자의 BMP는 앱 자체 그리기이며 데스크톱 캡처가 아니다. 실제 파일 선택 대화상자·물리 마우스·다른 DPI/PC의 사용은 별도 확인이 필요하다.

`build*/`에는 검증용 노트 덤프·개인 경로가 생길 수 있으므로 Git/배포에서 제외한다. 자체 코드는 부모 프로젝트와 같은 MIT 라이선스이며, osu! 계산식 및 정적 런타임의 고지는 배포의 `third_party`에서 확인한다.
